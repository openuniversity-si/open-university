# Audit and plan before commits (Daniel, Oct 26 23:26; after intake and research since Oct 29, D-077)

Every session runs two phases before its first code commit, after INTAKE and RESEARCH (intake-and-research.md). The audit reads intake.md and research.md as inputs, to know the real problem and the state of the art, and builds its own questions; neither file dictates what it checks:
1. AUDIT (read-only; parallel read sub-agents allowed): read the brief, intake.md, research.md, the PR/branch state, the files in scope and their tests (scripts/lib/gate-script-tests.json covers), the known-defects list, and what already exists that the brief may duplicate. Do NOT run full suites here; only cheap evidence. audit.md (template docs/process/templates/audit.md) carries `## Entradas` (links to the intake.md and research.md it read) and `## Distância do estado da arte` (where our current code stands against research.md's reference: what we have, what is missing, which rung of the ambition ladder we are on); the `structure check` refuses a new unit's audit.md without them.
2. PLAN: write the plan as the PR DESCRIPTION, section "## Plan" (order: at launch, BEFORE the audit, create your branch and open the PR as a DRAFT whose description is the brief summary. Intake, research, audit and plan are FILES in the repo with their own commits: docs/units/<unit>/intake.md, then research.md, then audit.md (findings and evidence), then plan.md (the Plan below). The PR description mirrors plan.md. Only then code commits. If the plan changes, commit the new plan.md and update the description; an existing PR adds these files the same way). It contains: (a) the commits as a dependency graph, each with the files it owns (no file owned by two parallel commits) and which run in parallel; (b) premises, each with its blast radius; mark any premise whose failure would change scope, spend money, touch production or the source of truth as CRITICAL; (c) the targeted tests per commit and the single final gate; (d) known base defects expected and their owners; (e) the block `## Cheapest useful effort` with `Action:`, `Cost:`, `Requirement:` (an owner, never the gate, the train or the tests) and `Cheaper rejected:` (effort.md; the gate refuses a plan or PR body without it).
Then execute at once (decide, then report): parallel commits via sub-agents per the graph, small pushed commits. A CRITICAL premise you cannot verify cheaply: pick the safest reversible option, act, and flag it in the Plan. If the plan changes, edit the PR description and say so in one comment.
