# Audit and plan before commits (Daniel, Oct 26 23:26; after intake and research since Oct 29, D-077; root causes and alternatives since Oct 29 18:15, D-081)

Every session runs two phases before its first code commit, after INTAKE and RESEARCH (intake-and-research.md). The audit reads intake.md and research.md as inputs, to know the real problem and the state of the art, and builds its own questions; neither file dictates what it checks. Incident (Oct 29): #805 false conflict → #807 → #804 refused → #808 → #809; four patches, one layer at a time, because each audit stopped at its PR's symptom and each plan did the first fix that came to mind. Five whys at #805 reach the structural cause at once: toolchain identity depended on the runtime environment, not on hermetic committed inputs.
1. AUDIT (read-only; parallel read sub-agents allowed): read the brief, intake.md, research.md, the PR/branch state, the files in scope and their tests (scripts/lib/gate-script-tests.json covers), the known-defects list, and what already exists that the brief may duplicate. Do NOT run full suites here; only cheap evidence. audit.md (template docs/process/templates/audit.md) carries `## Entradas` (links to the intake.md and research.md it read), `## Findings` (numbered, each with evidence), `## Causas raiz` and `## Distância do estado da arte` (where our current code stands against research.md's reference: what we have, what is missing, which rung of the ambition ladder we are on).
   `## Causas raiz` (5 Whys + fishbone, blameless): one `### R<n>. <title>` per root cause; several causes are several branches, each its own chain. Each root carries `Cadeia de porquês:`, a numbered list `1. Por que …? …` of at least three whys (usually about five) that stops only at a STRUCTURAL cause we control: a missing rule, a missing mechanism or a wrong design. "Someone made a mistake", "a flaky run" or "bad luck" is never a stop: ask why the system let it happen. Then `Classe:` with exactly one of `bug local` | `regra faltando` | `mecanismo faltando` | `arquitetura/desenho`, and `Evidência:`. The audit still proposes NO solution (decoupling, D-077): it states causes with evidence; options belong to the plan.
2. PLAN: docs/units/<unit>/plan.md (template docs/process/templates/plan.md); the PR DESCRIPTION, section "## Plan", mirrors it. Order: at launch, BEFORE the audit, create your branch and open the PR as a DRAFT whose description is the brief summary. Intake, research, audit and plan are FILES in the repo with their own commits: docs/units/<unit>/intake.md, then research.md, then audit.md, then plan.md. Only then code commits. If the plan changes, commit the new plan.md and update the description; an existing PR adds these files the same way. The plan decides before it executes:
   - `## Alternativas`: for each root of audit.md whose class is structural (`regra faltando`, `mecanismo faltando`, `arquitetura/desenho`), a `### R<n>` with a table of 2–4 alternatives `| A<k> … | <nível> | …`, at different levels: `remendo` (the symptom), `corrige a classe` (every instance of the cause), `redesenho` (the state of the art from research.md). Criteria columns: resolve a raiz?, custo, reversibilidade, risco, degrau (rung of the escada de ambição). A `bug local` needs no alternatives.
   - `## Escolha`: one line per structural root, `- R<n> → A<k>: <justification against the criteria>`. Choosing a `remendo` is allowed only with the reason and a `Follow-up:` on the same line or the lines under it, naming where the root will be fixed (a unit, an issue, a PR).
   - Then, as before: (a) the commits as a dependency graph, each with the files it owns (no file owned by two parallel commits) and which run in parallel; (b) premises, each with its blast radius; mark any premise whose failure would change scope, spend money, touch production or the source of truth as CRITICAL; (c) the targeted tests per commit and the single final gate; (d) known base defects expected and their owners; (e) the block `## Cheapest useful effort` with `Action:`, `Cost:`, `Requirement:` (an owner, never the gate, the train or the tests) and `Cheaper rejected:` (effort.md; the gate refuses a plan or PR body without it).
The `structure check` refuses a unit or program folder first committed at or after `intake.root_cause_since` (`config/registry/intake.json`) whose audit.md has no `## Causas raiz`, a root without a chain of at least three whys or without a known `Classe:`, or whose plan.md has no `## Alternativas` with 2–4 alternatives for each structural root, no `## Escolha` naming one of them for each structural root, or a `remendo` choice without `Follow-up:` (`scripts/lib/unit_intake.py`); older folders are not judged.
Then execute at once (decide, then report): parallel commits via sub-agents per the graph, small pushed commits. A CRITICAL premise you cannot verify cheaply: pick the safest reversible option, act, and flag it in the Plan. If the plan changes, edit the PR description and say so in one comment.
