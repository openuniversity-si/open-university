# Programs: avaliação → pesquisa → diagnóstico → solução → phases → retro (Daniel, Oct 30 16:19 BRT, D-115)

Applies only to a program: a set of PRs that brings a solution to the ideal (`docs/programs/<program>/`). A unit or an ad hoc task keeps intake → research → audit → plan (intake-and-research.md, audit-and-plan.md). Incident (Oct 30): GATE-SPEED was framed as "speed up the gate" when it was a whole test-management system, and coverage was missed because no step measured a baseline before deciding.

Central rule: every complaint exists because we live in a contingent world, not the ideal one. Ask "which ideal system failed here?" The answer is always a system that does not exist yet and must be built, or an existing system that must be improved. Blame lies with a system, never with chance or people.

1. AVALIAÇÃO, `avaliacao.md`: step back to first principles. `## Pedido` (literal, who and when), `## Sintoma`, `## Sistema que falhou` (missing: build it; existing: improve it), `## Sistema ideal`, `## Distância` (where we stand against the ideal). Then a metrics panel (Daniel, Oct 31 11:10 BRT, D-133; common sense, no rigid rule): the objective in one sentence, one main metric (the one that pulls) and the complementary metrics (the ones that keep the main one from improving without meaning), each with one line on why it matters and what is acceptable; a program may name two main targets when its objective has two faces.
2. PESQUISA, `pesquisa.md`: how the world's best do it. `## Quem faz melhor` (3–5 real references, what each does), `## Encaixe em nós` (copy, adapt or does not fit, and why).
3. DIAGNÓSTICO, `diagnostico.md`: measure before deciding. `## Métrica principal`: ONE metric; it may be a proxy, and then it states its gaps. `## Métricas de guarda`: what must not get worse (test coverage, test count, …), re-measured every phase. `## Linha de base`: each metric's value, where and when it was measured, and the command.
4. SOLUÇÃO, `solucao.md` (Daniel, Oct 31 10:27 BRT, D-132): an unlock graph in the Mikado style from the current system to the ideal one the avaliação defined: each node one change, its prerequisites, and its estimated gain on the main metric. `## Fases` cuts the graph into phases, one table row per phase, `| F<n> | target | what changes | stop criterion | size |`: a phase is the smallest coherent set of unlocks, closed under their dependencies, that delivers at least 10x measured on the main metric. 10x is a floor, not a ceiling: extend a phase while the gain per effort stays high (in orders of magnitude); a long chain that pays only at its end is one phase in several green PRs. After each phase, measure and redraw the graph. `## Critério de parada`: only the ideal system or a measured physical limit, recorded as a D-NNN; a cost-benefit or a measurement's noise is never one.
5. Per phase, `phases/F<n>.md`: `## Auditoria` asks why the work exists at all (why does the cold suite run everything? why does this process run?), not which slice is largest. `## Plano` lists the solutions from the most structural to the most superficial and executes them in that order (Daniel, Oct 31 09:44 BRT, D-132): (1) the redesign, the ideal system that would reach the phase's target; (2) inside it, every class problem; (3) only then the point issues left. Its alternatives keep their levels (remendo / corrige a classe / redesenho), and a choice that gives 5–10 % is never the plan of a phase: slicing the largest slice one at a time is linear optimization, and a phase must be geometric. Small commits, then `## Medição` with one fenced `json phase.v1` block: `{"main": {"name", "better": "lower"|"higher", "target", "value"}, "guards": [{"name", "better", "baseline", "value"}], "passed": true|false}`. The target of every phase is 10x on the main metric and it must be reached: a phase that misses it does not stop, it goes on with the next level of redesign until it does (Daniel, Oct 31 09:41 BRT, D-132). A phase passes only if the main metric reaches its target and NO guard metric gets worse. Measure in ABBA order with repetitions when the box's spread is close to the gain.
5b. At each phase's close, look at the whole panel and answer in the PR whether the objective improved or only the number (D-133).
6. RETRO, `retro.md` (retro-before-merge.md), over the whole program.

Order: STEP 0 (branch and draft PR), then each file as its own commit; the phases go to the PR as one comment. Measure where it is fast (the session's container); a slow target machine validates once, at the end. The `structure check` refuses a program folder first committed at or after `intake.program_since` (`config/registry/intake.json`) without avaliacao.md and pesquisa.md, with a listed section missing or empty, with a later file whose earlier one is absent, or with a phase whose `passed` contradicts its own numbers (`scripts/lib/unit_intake.py`); older programs and every unit keep v7's checks.
