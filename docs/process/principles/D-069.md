## How to read this file

- **Principle**: the rule, in English, as decided.
- **Enforced by**: the check that fails a PR when the rule is broken. *Exists* names a file or module on
  `mod/roadmap-integration` today. *Planned* names the check and the PR that delivers it (plan v3 ids C0, M2, M3, M6, M7,
  U0–U4, S1, P1; v3.1 ids O1, T1, S2, G1, R1, H1, B1, L1, N1, K1).
- A principle without a machine check is not done. Until its PR lands, a PR satisfies the principle by following it and
  by stating in its body which items it satisfies and how; it never improvises a parallel mechanism (one source of truth,
  item 1). Where an owning PR exists, the item waits for it.
- Every PR body lists the D-069 items its change touches and how it satisfies each.

## Shared contract v3: the normative formats

Every PR of the D-069 wave uses exactly these formats; no PR invents another. The owning PR named in each subsection
writes the files; this section is the reference they implement.

### Schema language (all owners)

- One language: **JSON Schema draft 2020-12**, for config, events, unit contracts and intents.
- Schemas live under `contracts/`: `contracts/config/`, `contracts/events/`, later `contracts/units/` and
  `contracts/intents/`. The version is in the file name, `<name>.v<N>.json`.
- A schema changes only by expand→contract (P-07, D-029): the new shape is added, each consumer migrates in its own
  lane, and the PR that moves the last consumer deletes the old shape.
- Python types are generated from the schemas (`scripts/generate python-types`), never written by hand alongside
  them. The TypeScript target left with the site, its last consumer (VAZÃO F56).

### Config registry (owner: C0, D-068, P-41)

Each owner declares its parameters in one file, `config/registry/<owner>.json`, which is itself a JSON Schema object:

```json
{"$schema": "https://json-schema.org/draft/2020-12/schema", "$id": "config/registry/<owner>.json",
 "x-owner": "<owner>", "x-schema-version": 1,
 "type": "object", "additionalProperties": false, "properties": {
   "<owner>.<snake_case_key>": {
     "type": "integer|number|boolean|string|array", "default": "<value>",
     "minimum": "<optional>", "maximum": "<optional>", "enum": ["<optional>"],
     "x-unit": "<s|ms|count|percent|lines|tokens|...>", "description": "<what it controls>",
     "x-readers": ["<path of each reader>"],
     "x-flag": "<true only for feature flags, optional>",
     "x-text": "<true only for user-facing text; the value is keyed by locale, e.g. {\"en\": \"...\"}; optional>"}
 }}
```

- Owners include `premises`, `forge-events`, `plan-tick`, `session-cache`, `config`, `train`, `battery`, `units`,
  `toolchain`, `slo`, `budgets`. The v3.1 delta adds the owners its PRs need.
- A name says what the value controls. One value has one name.
- Durations, timeouts, clocks, retry counts, seeds, thresholds, model choices, flags, SLOs and budgets are all registry
  entries.
- Secrets never go in the registry. They stay in the secret store; the registry may hold only a secret's name.

### Reading config (owner: C0)

- Python: `config.get("<name>")` from `scripts/lib/config.py`, imported the way sibling modules in `scripts/lib`
  import each other.
- Shell and `.mjs`: `python3 scripts/lib/config.py get <name>`, which prints the value as JSON.
- There is never an inline fallback. A missing name is an error, not a default in code.
- The v0 shim has one fixed text. PRs that need it before C0 lands create it byte for byte, and C0 extends it, keeping
  `get()` and the file format.

### Event envelope (owner: M2)

Every event is an envelope validated by `contracts/events/envelope.v1.json`:

| Field | Meaning |
|---|---|
| `event_id` | String. It is the idempotency key: sha256 of producer + type + natural key, so re-emitting is a no-op. |
| `type` | E.g. `config.changed`. |
| `version` | Integer; the payload schema is `contracts/events/<type>.v<version>.json`. |
| `occurred_at` | RFC 3339 UTC, from the injected clock, never read from the wall clock directly. |
| `producer` | Who emitted it. |
| `correlation_id` | Ties the events of one flow (a PR, a batch). |
| `payload` | Validated by the type's own schema. |

The log is append-only, and engine state must be rebuildable by replay. Until M2 merges, producers write events through
the port API in [EVENTS.md](../EVENTS.md) and this envelope; there is never a vendor call outside an adapter.

### Observability event `engine.step.measured` v1 (owner: M2)

Payload: `step`, `unit`, `pr`, `duration_ms`, `tokens_in`, `tokens_out`, `model`, `provider`, `result` (`ok`, `fail`
or `blocked`), `retries`. Every engine step emits one; SLOs (O1) and performance baselines (B1) are computed from these
events, never stored separately.

### Audit event `config.changed` v1 (owner: C0)

Payload: `name`, `old`, `new`, `actor`, `reason`, `at`. Each change to the registry emits one, so the log answers who
changed what, when and why. A revert is a new `config.changed`.
