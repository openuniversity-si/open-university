# The rule system (RULE-AUDIT)

The governing rule, Daniel, 17:09 BRT 28/10:

> "No rule survives on inertia; every rule answers its question, always, and a stop is only legitimate when its
> question exists and its root cause is named."

## Why it exists

- **16:52 and 16:55 BRT 28/10 (Daniel).** The registry owns every rule. No rule exists without a justification, an
  owner, a review date, an end condition, an impact statement and the premises it rests on, and no rule lives past its
  review date or end condition, or rests on a refuted or unvalidated premise, without showing up as a number. Premises
  build on the existing register (`docs/process/premises/*.yml`), never beside it. The first pass reports and refuses
  nothing.
- **17:08 BRT (Daniel).** Every stop of the flow is an accident. A check that stops the flow is itself questioned, the
  way Tesla treats a vehicle accident: a case with a mandatory root cause, never a statistic. That is the `stop_record`.
- **17:09 BRT (Daniel).** Questioning is always on. Every rule carries a standing question that must be answerable at
  any time, not only after a stop. That is the `question`.

The program decisions are D-069 item 9 (fix the class) and D-072 (a block enters an evaluation before any action).

## What is real now

| File | What it is |
|---|---|
| `config/registry/rules.json` | The registry file (owner `rules`): seven parameters, the records included. |
| `scripts/lib/rule_registry.py` | The library: pure functions over a `World` (records, settings, premises, decisions, `today`, `root`). |
| `scripts/rule` | The command line, a thin shell over the library. |
| `scripts/tests/test_rule_registry.py`, `rule.test.sh`, `covers/rule.json` | 28 hermetic tests (fixture checkouts at a fixed date, plus a smoke run on this checkout). |
| `units/engine-rules/unit.json` | The unit that owns these files (engine lane; requires `engine-config`, `engine-premises`). |
| `scripts/lib/generated/config_registry_rules.py`, `CODEOWNERS` | Regenerated by `scripts/generate python-types` and `scripts/generate codeowners`, never by hand. |

The system reads local files only. `main()` pins the configuration store to the checkout's local log, so no value is
read from the forge. It makes no network call and no AI call. The one write is `scripts/rule question <id> --answer`,
which appends an answer to `config/registry/rules.json` in the checkout and keeps the file's layout.

### Registry parameters

| Parameter | Default | What it controls |
|---|---|---|
| `rules.catalog` | one record (`R-rule-record-complete`) | The records. Its `items` schema checks each record's shape. |
| `rules.check_mode` | `report` | `report`: print everything, exit 0. `refuse`: exit 1 on what `refusals()` lists. |
| `rules.max_review_days` | 90 | Longest a `review_by` may lie after the later of `created.on` and `last_reviewed`. It can only tighten (`x-monotonic: max`). |
| `rules.stop_patterns` | `scripts/lib/*.py`, `^\s*def ([a-z_]*(errors\|refus\|reject\|block)[a-z_]*)\(` | How code that can stop a flow is found: the RULE-AUDIT census pattern, so both counts agree. |
| `rules.decision_register` | `docs/domain/DECISIONS.md` | Where a `D-NNN` that owns or retires a rule must be a row `\| D-NNN \|`. |
| `rules.census_file`, `rules.groups_file` | `docs/audits/rules/census.json`, `groups.json` | Read only, by `scripts/rule question <group>`. |

### The record

| Field | Needed by | What it says |
|---|---|---|
| `id` | every record | `R-<kebab>`, unique. |
| `statement` | every record | What the rule requires, in one sentence. |
| `where` | every record | Refs to the code or config that implements it: `path:function` or `path#key`. |
| `owner` | every record | A recorded `D-NNN`, or `<name> YYYY-MM-DD`. |
| `created` | every record | `{on, by}`. |
| `review_by`, `last_reviewed` | every record (`last_reviewed` optional) | A real date after `created.on`, at most `rules.max_review_days` after the later of the two. |
| `ends_when` | every record | `{kind, text}` plus `on` (date), `path` (path_exists, path_absent) or `key` and `equals` (registry_equals). `manual` never holds by itself. |
| `stops` | every record | Can it stop a flow (refuse, fail a gate, block a merge). A missing value is judged as `true`. |
| `premises` | every record | `P-NN` ids of the premise register. An unknown id is a gap. An empty list is a finding. |
| `question` | every record | `{text, answers: [{on, by, text}]}`. No answer yet is a finding. |
| `status`, `retired` | every record | `active` or `retired`. A retired record keeps `retired {on, by: D-NNN, reason}`. |
| `damage_if_passed` | stopping records | What goes wrong if the thing it stops gets through. |
| `impact_of_removal` | stopping records | `{positive, negative, measured}`. `measured` names the evidence and its numbers, or says plainly what is not measured and what would measure it. |
| `stop_record` | stopping records | `{count, source, measured_on, root_cause, cheapest_fix}`. A missing record or a null count means never measured. A count above 0 needs a root cause. |

The registry's own check (`config check`, part of `structure-check`) refuses a malformed shape: unknown keys, wrong
JSON types, an id, date or premise id outside its pattern, an unknown enum value. Everything else is counted by
`scripts/rule` and never refused while `rules.check_mode` is `report`.

### Commands

Every subcommand takes `--root DIR` and `--today YYYY-MM-DD` (default: today in UTC) and ends with a count line. A
usage error exits 2 through argparse.

| Command | Prints | Count line |
|---|---|---|
| `scripts/rule list` | one line per record | `rules: N (active, retired, stopping)` |
| `scripts/rule show <id>` | every field, each `where` ref's state, each premise's status and statement, the question with its latest answer, the stop record, the gaps | `rule <id>: N premise(s), N answer(s), N gap(s)` |
| `scripts/rule due` | `DUE` (review passed), `UNANSWERED` (review passed and no answer), `END` (end condition met or code gone, with the exact registry change) | `rules due: N` |
| `scripts/rule retired` | retired records, their decision and reason | `rules retired: N` |
| `scripts/rule stale` | every refuted, unsettled or undated premise with the rules that cite it, and a `STOPS` row per stopping rule on one | `stale premises: N` |
| `scripts/rule question <id>` | the standing question with the evidence: owner, created, review_by, stop record, premises with status, answers | `question <id>: N answer(s)` |
| `scripts/rule question <id> --answer TEXT --by WHO [--on DATE]` | appends the answer to `config/registry/rules.json` | the same |
| `scripts/rule question <group>` | the standing question of every census row of a group of `groups.json`, read only (the group audits answer them); exits 2 when `groups.json` or `census.json` is absent | `question <group>: N row(s), N with a question` |
| `scripts/rule check [--mode report\|refuse] [--base REF] [--json]` | every finding: `GAP`, `DUE`, `END`, `UNANSWERED`, `ACCIDENT`, `UNREGISTERED`, `PREMISE`, `DELETED`, and the counts | `rules check: ...; exit N` |

`--base REF` reads `config/registry/rules.json` at that ref with local git only. An id present there and absent here
left the catalog without a retirement.

## The flow

```
  AUTHOR                           CHECK (any event: a PR, a gate run, a person)          RETIRE
  a function that can stop   --->  rules.stop_patterns finds it
  a flow                           no active record lists it ........ UNREGISTERED (a stop without a question)
        |
        v
  a record in rules.catalog  --->  record_gaps ....................... GAP        a field is missing or invalid
  id statement where owner         review_by < today ................. DUE        (UNANSWERED if no answer too)
  created review_by ends_when      question without an answer ........ UNANSWERED
  stops damage impact              stop_record missing / count null .. ACCIDENT   never measured
  question {text, answers}         count > 0, no root_cause .......... ACCIDENT   no root cause
  stop_record                      ends_when holds, or code gone ..... END ---> the exact change:
  premises ----------+             --base: id gone from the catalog .. DELETED      "status": "retired",
                     |                                                              "retired": {on, by: <D-NNN>,
                     v                                                                          reason}
  docs/process/premises/*.yml      premise refuted, inferred,                       a person names the D-NNN,
  (P-NN: status, answer.at)  --->  to-validate or undated ............ PREMISE      a row of DECISIONS.md
  read by scripts/lib/premises.py  scripts/rule stale: every such premise, its rules, STOPS rows

  REVIEW: scripts/rule question <id> shows the evidence; --answer records the answer, last_reviewed and a new
  review_by restart the clock. report mode: every line above is a number, exit 0. refuse mode: exit 1 (below).
```

## A rule that fails its review date

It appears in `scripts/rule due` as `DUE <id>: review_by <date> passed N day(s) ago`, and as `UNANSWERED` when its
question has no answer either, and it is counted in `scripts/rule check` (`review: due N`). Report mode never refuses:
the date is evaluated when the check runs, an event, never on a timer (P-32). A person reviews it: answers its question,
sets `last_reviewed` and a new `review_by`, or retires it.

Refuse mode is the registry switch `rules.check_mode`, flipped only by an approved decision (a `D-NNN` row of
`docs/domain/DECISIONS.md`), in the change that retires `R-rule-record-complete` for a stopping record. Refuse mode
exits 1 when a stopping record has a gap, an unanswered question, no measurement, or a count with no root cause; when a
stopping function has no record; when a retirement lacks its recorded decision; or when a record left the catalog
without one (`--base`). A passed review date is never a refusal by itself: it is a number.

## Worked example 1: a premise failure (the WebKit case, Daniel 16:55)

**What happened** (A Torre's measurement): the gate treated the Open University site as if the gate machine could open
WebKit and reach it. On 28/10, 48 of 50 failures on PR #724 came from `webkit-mobile-390` `browserType.launch`, not
from the PR.

**What the register holds.** No premise says "the gate machine can launch WebKit". The only browser premise is P-26,
"cdn.playwright.dev and media.openuniversity.si are reachable from the cloud environment" (validated): it is about
reaching the download and media hosts, not about launching WebKit. The missing premise is itself the finding: the stop
rested on an assumption nobody wrote down, so nothing could count it.

**How the system turns it into a row** (an illustration: neither the premise nor the record exists yet):

1. `scripts/premises find "gate machine launch WebKit"`, then `scripts/premises propose` the premise "The gate machine
   can launch WebKit." It takes the next free id, P-53 today. Its answer is `refuted`, with A Torre's measurement as
   the evidence.
2. The rule that stops, the browser stage that runs `webkit-mobile-390`, gets a record with `premises: ["P-53"]`,
   `stops: true` and `stop_record: {count: null, source: "A Torre's measurement: 48 of 50 failures on PR #724 on 28/10
   came from webkit-mobile-390 browserType.launch", root_cause: null, cheapest_fix: null}`. The count stays null: 48 of
   50 counts failures, not the times the stage stopped a PR, and nothing here counted those.
3. `scripts/rule stale` then prints the row with its dependent-rule count, and `scripts/rule check` prints the premise
   and the accident:

```
P-53 refuted (high): rules 1 [R-gate-e2e-webkit]: The gate machine can launch WebKit.
STOPS R-gate-e2e-webkit rests on P-53 refuted: The gate machine can launch WebKit.
stale premises: 32 (cited by 1 active rule(s), 1 of them stopping)
...
ACCIDENT R-gate-e2e-webkit: stops the flow and has never been measured (stop_record.count is null)
PREMISE R-gate-e2e-webkit (stops): rests on P-53 refuted
```

The test `test_daniel_fixture_a_rule_on_a_refuted_premise_is_stale_one_on_a_confirmed_premise_is_not` proves this row
on a fixture: the rule on the refuted WebKit premise appears in `stale`, and the rule on a confirmed premise does not.

## Worked example 2: "conflicting" is a stop (Daniel 17:08)

**What happened** (A Torre's measurement, 28/10): 15 PRs were reported as "conflicting". 11 of them conflicted on
exactly one generated file, `apps/web/tsconfig.paths.json` / `apps/web/tsconfig.json`, four lines each, because a change
of that same day (TX32, commit 30740480, "the @ou/ address map moves to a generated apps/web/tsconfig.paths.json")
moved the @ou/ address map to a generated file. Nobody had asked why. The verdict "conflicting" was the accident, not
the cause.

**The rule it generalises to.** A report that says a unit cannot proceed is a stop, so it needs the same treatment as a
red gate: a cause, not a status word.

**How the system carries it.** The stop that printed "conflicting" gets a record (its `where` is named by the group
audit; the event that carries a conflict verdict today is `pr.conflicted`, `contracts/events/pr.conflicted.v1.json`),
with:

```json
"stop_record": {
  "count": 11,
  "source": "A Torre's measurement, 28/10: 11 of 15 PRs reported as conflicting conflicted on exactly one generated file, apps/web/tsconfig.paths.json / apps/web/tsconfig.json, four lines each",
  "measured_on": "2026-10-28",
  "root_cause": "the generated file moved by TX32 (commit 30740480): the @ou/ address map became generated",
  "cheapest_fix": "regenerate the file on merge instead of hand-merging it"
}
```

Before anyone asked why, the same record with `root_cause: null` prints
`ACCIDENT <id>: stopped the flow 11 time(s) (...) and no root cause is named`, and refuse mode would refuse it. With
the cause named, the row goes away. The other 4 of the 15 are not explained by this cause; one stop record carries one
cause (next unit 8).

## Limits of this first pass

- Discovery is the census regex: functions named `*errors*`, `*refus*`, `*reject*`, `*block*` in `scripts/lib/*.py`.
  A stop elsewhere, or named otherwise, is not counted yet (next unit 4).
- A `where` ref is checked by a `def`/`class` match in Python, a whole-word match in other files, and a key of
  `properties` or the top level in JSON.
- A `rules.*` override in the shared configuration store (on the forge) is not read: the system reads the registry and
  the checkout's local log only, so the record a PR changes is the record that counts.
- "Undated" means the premise's current status carries no date (`answer.at` for an answered premise, `source.at` for an
  open one). "Unsettled" and "refuted" are the premise register's own classes (`premises.open_statuses`,
  `premises.refused_statuses`), not a second list.
