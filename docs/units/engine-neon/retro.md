# engine-neon retro (U4)

1. **Brief quality.** The brief asked for `units/engine-neon/` moves and a manifest contract, but also said "if no address form for Python/shell, keep in place". Unstated: a filled `contract` slot turns `unit-battery` red for an addressless unit (found by reading `unit_battery.plan`, same finding as engine-wrappers #597). The brief's branch name (`mod/u4-engine-neon`) differed from the harness branch (`claude/u4-engine-neon-fnorb4`); the harness one was used.
2. **Audit and plan.** P-03 held (no Python address). The plan did not change. The battery was `ok` with zero steps at the start: the unit's Python test sat in another unit's script (`cloud-tail.test.sh`), so the battery proved nothing. That was the audit's main finding.
3. **Execution** (times UTC): 06:47 plan, 06:52 registry (20 `neon.*` entries, three modules), 06:57 battery step + manifest + generated, 06:58 base merge (picked up #597), contract.md, this retro. Failures: structure-check named a missing `requires: engine-config` after the modules imported `config` (class: a new import edge must update `requires`; U2 caught it at once). Dead end: the first gate was launched with a `&` inside a background call, leaving two runs contending for `.gate/gate.lock`; one run was enough (class: launch a gate once, as a foreground command of a background task). Registry-backed tests slowed from 0.009 s to ~0.7 s because `config.get` re-reads the registry per call (owner: engine-config, a cache would help; still far inside `battery.unit_time_limit`).
4. **Gate.** One effective run on head 36ff339b: PASSED in 707 s wall (ceiling warning, D-064 f; mostly queue time behind the contended lock, structure check 58.8 s, script tests 63.1 s). Two script-test failures were reported and did not block the recorded pass: `generate.test.sh` (Node module not installed in this container, environment) and `premises.test.sh` `test_repository_register_is_valid` (also red on a clean checkout of the base: base defect, owner premises). The same head is re-gated after this docs-only commit.
5. **Lessons.** (a) The brief template for Python units should say that the `contract` slot stays empty until units.address covers non-TS units, and point to `docs/units/<unit>/contract.md` (owner: engine-units/U-series coordinator). (b) `config.get` should memoise the registry per process (owner: engine-config). (c) A unit whose tests live in another unit's script should get its own `scripts/tests/<unit>.test.sh` in its manifest: a battery check "unit has files but zero steps" would catch it (owner: engine-units, G1/K1).
