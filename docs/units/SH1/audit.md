## What exists
- Manifest loader: `scripts/lib/units.py` — `manifests(root)` (valid manifests by id, line 164), `claims_of(path)` (line 176), `matcher`/`compile_glob` (lines 61-77). It reads the working tree; the train reads manifests at a *commit* through `UnitOwnership.manifests(commit)` (`scripts/lib/train_ownership.py:18`, `ls-tree` + `git show`, glob `train.unit_manifests`, `config/registry/train.json:276`). SH-1 reuses that commit reader (no second loader) and matches paths with `gate_areas.glob_match`, exactly as `refusals()` does (`train_ownership.py:46`).
- Manifest shape: `paths` (globs), `requires` is an object `{unit-id: "^1"}` (e.g. `units/app-api/unit.json:9`). Dependents of U = units whose `requires` names U, transitively.
- Train: `Train.start_batch` (`scripts/lib/train.py:197`) builds the combined head and emits `train.batch.started` at line 205-207. Per-member files already come from `self.workspace.changed_files(base, entry.sha)` (`train.py:173`, impl `scripts/lib/train_git.py:77`: `git diff --name-only base...head`), the same call the ownership check uses. `Train.ownership` (`train.py:132`) holds the `UnitOwnership` (None in some tests).
- Settings are read in `Train.__init__` via `engine_role.setting` (`train.py:130-148`).
- Event contract precedent: `contracts/events/train.batch.started.v1.json`; row at `docs/process/EVENTS.md:43`.
- Generated outputs: `generate.targets` (`config/registry/generate.json`): committed outputs are `scripts/lib/generated`, `contracts/generated/typescript`, `apps/web/src/generated/text`, `CODEOWNERS`, `apps/web/tsconfig.paths.json`.

## Corrections to the brief (verify cited sources)
- The brief names `apps/web/tsconfig.json` as a generated aggregate. On base the generated file is `apps/web/tsconfig.paths.json` (the `addresses` target; `tsconfig.json` only extends it and is hand-written). SH-1 derives the generated set from `generate.targets` (committed outputs), so `CODEOWNERS` and `tsconfig.paths.json` are generated; a test quotes both and asserts `tsconfig.json` is NOT silently classed as generated.
- `train.published_aggregates` is empty and `train.publish_aggregates` false today; it cannot be the source of "generated", so `generate.targets` is.

## Constraints
- `key()` must be pure: it takes the manifests (already loaded) and the file list; the forge/git reading stays in a thin wrapper.
- The event is a new type; `forge_events` / `event_contracts` validate payloads against `contracts/events/<type>.v1.json`; the generated TypedDict module is regenerated by `scripts/generate`.
