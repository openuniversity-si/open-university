# KF3 retro

1. **Brief.** Clear on the symptom and the ban on raising timeouts. Gaps: it did not say the claude-session drop already isolated its database and killed connections, nor that the stall is not reproducible off the loaded gate; the "expected value varies with CPU count" is really a start-time race.
2. **Audit and plan.** P2 (heavy-db is a pure timing race) held. P1 (30 s stall = checkpoint contention on the shared cluster) is unconfirmed: a drop took at most 1.5 s with 8 parallel create/drops and with 6 write loads. The plan added a registered lock and timeout diagnostics instead of a proof; if the stall recurs it is an incident and the diagnostics name the cause. The plan did not foresee the literal census, generated types and hermetic wall-clock rules.
3. **Execution.** Commits: audit f06bd326, plan 805889c2, rendezvous 23d243e4, test_db lock 7ebbed50, guard 6c0cdd30, class fix 7a373374, base merge a07a14d6. Failures: (a) the first rendezvous took the expected peak from the cap, which is wrong for uncapped stages (found by stressing with 8 busy loops); (b) the first gate (17m45s, 6c0cdd30) failed on 4 rules my change broke: literal census (new number literals in test_db.py, gate-heavy-db and the guard), generated registry types not regenerated, `wall_clock` in a unit test, baseline list not shrunk. One class: I ran only the targeted tests, not structure-check, `generate`, `literals`, `hermetic`. Wait time: ~18 min per gate; the two sub-agent levels of the brief were skipped (small unit).
4. **Gate.** Run 1 on 6c0cdd30: FAILED (the 4 rule failures above; generate.test.sh also hit the base defect fixed by KF2r). Run 2 on a07a14d6 (after merging base 39c11cba): PASSED, 637 s (script tests 518 s; ceiling 180 s exceeded, a base condition).
5. **Lessons.** (i) Local check set for gate-lane PRs should include `structure-check`, `scripts/generate --check`, and the literals/hermetic tests; owner: local-checks registry (`config/registry/local-checks.json`). (ii) Any test that counts concurrency should use the rendezvous pattern (guard added covers host-derived values only; a shared `peak_of` helper would be the next step). (iii) Briefs for flaky tests should carry a reproduction under load; owner: coordinator.
