# gate-speed — F5: ≤ 60 s

Phase 5 of the [solução](../solucao.md) (D-122, Daniel's order: the train's git work batched after the fork server).
F4 left the suite at 96.2 s cold on 4 vCPUs and 319.2 CPU-s ([F4](F4.md)).

## Auditoria
Measured on F4's head (`91bfe263`) in the session container, each train test file alone, then the train's own git
calls counted by shape and caller:
1. **The train asks git the same question about the same objects again and again.** `train/test_verdict.py`, the
   longest file of the longest script test (`train.test.sh`, 60.8 s of committed cost), runs 2,340 processes in
   18.8 s; 1,205 of them are the train's own `GitWorkspace.git`: 301 `fetch` (130 for a branch tip, the rest for a
   commit), 293 `rev-parse --verify`, 149 `ls-tree -r` (the unit manifests of the same tip, once per PR), 121
   `diff --name-only`, 160 `merge-base`, 46 `show -s`. Every one of those reads names only object ids, whose answer
   cannot change, and a `fetch` of a commit the repository already holds still starts the transport (five processes
   for nothing). The system that fails: a git answer is treated as free, so each train step asks again; git_objects
   (GATE-SPEED R2) already remembers file contents by sha, the rest of the workspace does not.
2. **Fixtures drop the hermetic git configuration.** Seven fixtures (the train's, the planner's, the quarantine's,
   the gate batch's and pin's, a root probe and `gate-pin.test.sh`) point `GIT_CONFIG_GLOBAL` at `/dev/null`, the
   file F1 made hermetic: every commit and push they make runs git's automatic maintenance again (`maintenance run
   --auto` 1,343 times and `gc --auto` after each push, in a cold run). The system that fails: the hermetic settings
   live in a file a fixture can swap out.

## Plano
| Root | Alternative | Level | Choice |
|---|---|---|---|
| 1 | A1: memoize at each call site (the manifests, the ancestry checks) | remendo | no: the next call site asks again |
| 1 | A2: `GitWorkspace` remembers every answer of a read whose operands are object ids alone (`rev-parse`, `ls-tree`, `diff`, `merge-base`, `show -s`, `cat-file -e`, `rev-list --count`; a definite "no" of `--is-ancestor` too, never a missing object), and `fetch` skips the commits it already holds (one `cat-file --batch-check` for all) | corrige a classe | **yes** |
| 1 | A3: one long-lived `git cat-file --batch` per workspace answering every read | redesenho | later: a process to own and stop, for what A2 leaves |
| 2 | A1: fix the seven fixtures | remendo | no: the eighth swaps it again |
| 2 | A2: the hermetic settings also through the environment (`GIT_CONFIG_COUNT`, `gate.test_git_overrides`), which applies over any file; no identity there, a test sets its own | corrige a classe | **yes** |

Commits: (1) this audit and plan; (2) the workspace's remembered answers and fetch, with tests; (3) the git settings
through the environment, with a test; (4) the measurement. Tests: `scripts/tests/train/test_git_answers.py`, the
train's script tests, `scripts/tests/test_gate_test_cache.py`, and the whole suite through `scripts/test-suite
