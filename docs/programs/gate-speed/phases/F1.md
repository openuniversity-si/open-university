# gate-speed — F1: ≤ 60 s

Phase 1 of the [solução](../solucao.md) (D-116): the box stops leaking into the tests, and the long tail gets the free
CPUs. Baseline 169.1 s cold on 4 vCPUs ([diagnóstico](../diagnostico.md)).

## Auditoria
What limited `cold_wall_s` at the baseline, measured:
1. **The box leaks into the tests.** The hermetic rules isolate the network, the clock and the random seed, never git:
   every fixture commit inherits the box's global configuration. This box signs each commit with an external program
   (80 ms against 7 ms unsigned, 10 commits each way), and git spawns `git maintenance run --auto` after commits and
   fetches (2,016 of them in a partial exec trace of the suite). Three test files isolate git by hand; the rest inherit
   whatever the box has, so cost and verdict depend on where the suite runs.
2. **The long tail idles the box.** 3.1 of 4 CPUs busy on average: the four longest tests (structure-check 59.7 s,
   train 54.6 s, push-guard 44.2 s, train-reuse 39.6 s) end the run on one CPU each. D-076 fixes each test's share of
   the CPUs when the run starts and never hands a freed CPU to the tests still running.
3. **Found while measuring the first two: the suite is bound by CPU, and the CPU by processes.** 520–540 CPU-s, a
   floor of about 130 s on 4 vCPUs with perfect packing; 60 s needs fewer than 240 CPU-s. The signing cost was waiting,
   not CPU (it moved the wall, not `cpu_s`). A partial exec trace of the suite counts about 127,000 processes, 42,000 of
   them git (rev-parse 7,522, show 4,447, add 2,884, commit 2,434, init 2,034) and about 1,100 Python; a git process
   costs 3–5 ms of CPU, mostly system time (fork, exec, page faults), and a Python process 50 ms with the hermetic
   harness (11 ms bare). Per test (each alone, one CPU): push-guard 71 CPU-s, structure-check 57, train 54,
   train-reuse 36, prepush 21; the top four are 42 % of the suite. The system that fails: tests build their fixtures
   and call the engine through new processes for every case (no fixture is built once, no CLI is called in process).

## Plano
| Root | Alternative | Level | Choice |
|---|---|---|---|
| 1 | A1: each slow test sets `commit.gpgsign=false` itself, as three already do | remendo | no: the next test repeats the leak |
| 1 | A2: the suite runner gives every script test one git configuration of the judge's checkout (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`): a fixed identity, no signing, no automatic maintenance or gc | corrige a classe | **yes** |
| 1 | A3: every test in a private HOME with nothing of the box | redesenho | later: tests that build their environment from scratch still reach the box's config (42 signing calls in push-guard) |
| 2 | A1: a larger `OU_TEST_CPUS` for the four long tests by name | remendo | no: the list goes stale |
| 2 | A2: a jobserver (GNU make's `-j`): once no test is left to start, a test that ends hands its CPUs, as FIFO tokens, to the tests still running; `parallel_tests.py` takes a token for each extra file | corrige a classe | **yes** |
| 3 | fixtures built once and copied, the engine called in process, a lighter Python start-up | corrige a classe | the next phase: it is the whole restructuring the solução put in F2 |

Rejected after measuring: a box-level bytecode cache (`PYTHONPYCACHEPREFIX` with writes re-enabled under
`PYTHONDONTWRITEBYTECODE`). A process importing `config` costs 205 ms of CPU without bytecode and 56 ms with it, but
within one run the tree's own `__pycache__` warms up after the first tests, and the prefix, which hides that cache,
measured 541 CPU-s against 510 without it.

Commits: (1) this audit and plan; (2) hermetic git and the jobserver, with their tests; (3) the measurement below,
the stop of D-118 and the v7 adapter files of D-117 deleted (the base now runs v8). Tests: `test_gate_test_cache.py`,
`test_gate_graph.py`; the whole suite through `scripts/test-suite --metrics`.
