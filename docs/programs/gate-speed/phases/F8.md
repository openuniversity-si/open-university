# gate-speed — F8: ≤ 10 s

Phase 8 of the [solução](../solucao.md): the redesign below the floor of the tests as written (D-126: about
250 CPU-s while tests start git where git is not their subject). Daniel's rule (D-122, the vigia's 31/10 order):
cost-benefit is no stop above about 10 s; only a measured physical limit is. One step per PR.

## Auditoria
Measured on `d0e5960d` (F7 merged) in the session container:
1. **The train's tests run git's transport for a forge that lives on the same disk.** `train/test_verdict.py`
   makes 2,299 processes; the largest share is the train workspace's `fetch` (222 calls, 3.0 s of its 10.5 s in
   processes), each one the local transport (fetch, upload-pack, pack-objects, rev-list, index-pack). The train's
   tests are about a quarter of the suite's CPU and are not about the transport: the forge is a fake, and the
   workspace's fetch and push have tests of their own (`train/test_git_answers.py`). The system that fails: the
   fixture's workspace is the production one end to end, so every test pays the part only a few are about.

## Plano
| Root | Alternative | Level | Choice |
|---|---|---|---|
| 1 | A1: fewer train steps per test | remendo | no: a test runs the steps its assertion needs |
| 1 | A2: a fixture workspace (`FixtureWorkspace`) whose checkout and the forge's origin read each other's objects in place (`--shared` and `objects/info/alternates`): a fetch copies the origin's ref, a push sets it (refused unless it fast-forwards, as `git push`); every other git call is the production workspace's; the workspace's real fetch and push stay judged against a real remote, on a checkout of their own | corrige a classe | **yes** (step 1) |
| 1 | A3: the whole workspace in memory (refs, trees, merges) | redesenho | no: `merge-tree` and `commit-tree` are what the train's merge tests judge |
