# gate-speed — F2: ≤ 60 s

Phase 2 of the [solução](../solucao.md), re-planned by D-118: processes are paid once. F1 left the suite at 163.4 s
cold on 4 vCPUs and 531.7 CPU-s ([F1](F1.md)); the wall is bound by `cpu_s / 4`.

## Auditoria
Measured per test (each alone, one CPU) and per file, what the CPU and the wall pay for:
1. **Fixtures copy what they never read.** Since D-099 `config/registry` holds about 900 per-key source files next to
   the 60 aggregates `config.get` reads. Eleven fixtures copied the whole folder for every test case: 240 ms of CPU a
   copy against 4 ms for the aggregates, and every later `git add -A` of the fixture hashed the 900 files again.
   `train-reuse` committed 944 files into a fresh repository for each of its 17 tests (36 CPU-s). The system that
   fails: no shared rule says what a fixture copies, so each test kept copying the folder it knew before the split.
2. **Tests run machinery that is not their subject.** The push guard's fixture pointed `core.hooksPath` at the
   checkout's hooks, so every fixture push ran the whole pre-push check (`commit_check --local`, `prepush --hook`),
   which local-checks and prepush judge on their own: 42 CPU-s for 21 tests about post-commit, replay and stalls.
3. **The engine is called through a new process when its function is the subject.** `StructureCheck`'s 32 tests
   started `bash scripts/structure-check` (bash, Python, the hermetic harness, every import) for each assertion,
   although the wrapper only execs `structure.main` (25 → 17 CPU-s in process).
4. **A box with no history runs the long tests last.** The gate orders longest first by the durations a box records;
   a fresh box (this session, a new runner, a hosted runner) has none, so the suite starts in discovery order and the
   longest tests (train, structure-check) begin when the others end: 117 s of wall against 87 s of `cpu_s / 4`.
   The system that fails: the order depends on a history that only an old box has.

Measured and left out: building the train's three fixture repositories once per class saved 2 of 56 CPU-s (the cost
is the train's own git work under test, 18,600 git processes, which the next phase weighs).

## Plano
| Root | Alternative | Level | Choice |
|---|---|---|---|
| 1 | A1: each slow test copies less by hand | remendo | no: the next fixture copies the folder again |
| 1 | A2: one helper, `scripts/tests/fixture_copy.py`: the registry's aggregates by default, its sources only for a test of the sources | corrige a classe | **yes** |
| 1 | A3: one copy-on-write fixture store for every test of the run | redesenho | later |
| 2 | A1: an environment switch that makes the pre-push hook skip its checks | remendo | no: a production hook a variable turns off is a weakened check |
| 2 | A2: the fixture installs the hooks under test (post-commit, post-merge) as the checkout ships them, under a root whose `scripts/` is the checkout's | corrige a classe | **yes** |
| 3 | A1: in process for `StructureCheck`; the one test of the wrapper keeps the process | corrige a classe | **yes** |
| 3 | A2: a warm fork server for every engine command a test starts | redesenho | F3 |
| 4 | A1: list the long tests first by hand | remendo | no: the list goes stale |
| 4 | A2: committed cost hints, `scripts/tests/costs.json`, written by `scripts/test-suite --metrics --write-costs` from a cold pass; a box with recorded durations keeps using them | corrige a classe | **yes** |
| 4 | A3: a shared duration store every box reads | redesenho | with the shared cache, later |

Commits: (1) this audit and plan; (2) `fixture_copy` and the fixtures that copied the registry; (3) the push guard's
hooks without pre-push and `StructureCheck` in process; (4) the cost hints; (5) the measurement. Tests: the changed
