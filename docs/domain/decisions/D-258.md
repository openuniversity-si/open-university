A run names its own report, and a verdict is read from that report, never from the newest report on disk or from an exit code: the gate-shadow verdict and the red tail of `gate-dev` (lane 11, reserved for the shadow PR by lane 1).

Case: e2a45feb0 was measured FAILED by the shadow, and its own report says FAIL (script tests: `git commit-tree -F`, an ambiguous argument); the exit 1 was right. The line "gate-dev --why: ... passed; nothing failed" that the shadow kept as its tail named another run's report (PR #961, 7cc5beaf), the newest folder under `.gate/records/reports`, because `gate-dev --why --latest` asks for the newest report of any sha and any tree.

Three levels. Design: a red run asks a shared index ("the newest report on disk") about itself, and the shadow judges a run by a file it finds by age (the newest `stages.json` since the start). Class: a run's answer is read from a place that other runs also write, instead of from a folder the run was given. Case: the tail above, and a shadow that could pick another run's report if two wrote at once.

Alternatives for the class (the root is structural, so no remendo alone):
- A (remendo): filter `--latest` to the same sha. Still a shared index: two runs of one sha, or a report-only run next to a records run, still pick the wrong folder.
- B (corrige a classe): the caller names the folder through `GATE_REPORT_DIR` (the pattern `gate_noite` and `gate_verdict` already use), and the shadow and `gate-dev` read the verdict from that folder. Chosen: a run answers only about the folder it was given.
- C (redesenho): a verdict line written into each report and printed by the run. It duplicates B's folder and adds a second file to keep in step with `stages.json`.

Choice: B. The shadow sets `GATE_REPORT_DIR` to a folder under `.gate/report-only/reports/<sha>/` it creates for the run and reads that `stages.json`; the exit code decides only when no report was written. `gate-dev` (no `--pr`) sets `GATE_REPORT_DIR` to a folder it creates under `.gate/records/reports/`, and its red tail asks `gate_explain.py why` about that folder. The test that fails before the change: the tail's `why` call gets `--latest` and not the run's folder. The shadow moves to `engine-gate-verdict` (the manifest of `engine-gate-ops` loses its four paths), because lane 1 gave it to lane 11.

Not changed: `gate_explain why --latest` (a user asking for the latest report still gets it); gate-gc's bound on the records folders.
