**The site's promotion guard is the Torre's step before the build, not a step inside it (Torre por delegação do Daniel 22/11/2026; amends D-363 (a); D-363.md is not edited, D-217).** D-363 ran `apps/web/deploy/promotion-guard.sh` from `build-image.sh` inside the CodeBuild project `open-university-web`, reading the commit's check runs anonymously. On 23/11 the first two real releases failed closed: 95280f7 on a wrapper bug (fixed by #370) and ceae4ed because GitHub refused the anonymous read (403) from CodeBuild's shared addresses, whose per-address limit other tenants exhaust, so the in-build guard would refuse every release. Giving the build a GitHub token would be a new long-lived key in the build's environment, and whoever may start a build may also override its buildspec, so the start-build permission is the boundary either way. So: the Torre runs `promotion-guard.sh <sha>` with `GITHUB_TOKEN` from its own GitHub login and starts the build only on exit 0 (green); red, running/absent or unreadable refuse. Everything else of D-363 holds: `main-health` stays out of the merge queue, `promotion-health` decides by the newest `full-suite` run on the exact SHA, and `full-suite.yml` keeps one `main-red-andon` issue. Residual: the guard is a step of the Torre's release, not enforced by AWS. Revert path: put the call back in `build-image.sh` once the build reads check runs with a credential it already holds (for example an App token), by a superseding decision.
