**PADRAO-DEV F8c: the architecture is layered, and a reflexion divergence is decided by its direction (the session's judgment, 17/11/2026, D-294).** The reflexion model (Murphy, Notkin, Sullivan 1995) found 29 dependencies between architecture elements that the units have and no element declared, and F4 required each to become a decision to accept or a unit to break, never a mass declaration. One rule decides all of them: the elements are layered by what stands on what, 0 config and events (the contracts and the logs), 1 planning, knowledge and environment (the registers), 2 the gate (it judges a change with the registers), 3 delivery (it moves a judged change), 4 deploy and the site (they run what was delivered), 5 measurement and the model (they observe everything). A dependency on the same or a lower layer is accepted and declared on the element with this decision as its basis (12 of the 29); one that goes up is a defect to break by moving the code or inverting the dependency (17, listed in docs/programs/padrao-dev/phases/F8.md). STD-architecture-layers refuses a declared dependency that goes up, so no upward dependency is ever accepted by declaring it. The reflexion share goes from 42 % to 65 % (34 convergences, 17 divergences, 1 absence); VAL-changeability asks 85 %, which the 17 breaks reach. The declared dependency of config on environment, with no code behind it, is removed. The proof is the test of scripts/model. Revert path: a later decision that supersedes this one.
