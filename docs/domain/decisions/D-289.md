The proof of absence, not a prior revision, decides when a registry parameter may leave. A parameter whose key nothing in the tree names any more leaves in the same change that stops needing it; a parameter a source file or a test still spells cannot leave until those readers are migrated, and the gate names them. The deprecated field keeps its use for contracts, whose data another party writes and whose readers this tree cannot measure. Measured cause: 17 forge-events.origin_* keys had no reader at all — the Origin client reads its settings from origin-client since D-068 — yet schema compat demanded a revision marking them deprecated, so retiring 17 dead parameters cost two PRs and left 21 stale-consumer and 17 unknown-key findings exposed in operation_check. The reader set is the one D-100 and D-153 already define (registry_readers), so absence is measured by the same rule the run selection uses: generated modules, prose and records are not readers.
