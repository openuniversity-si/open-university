**The site keeps unsafe-inline in its script and style policy, as a dated exemption of CTRL-ssdf-pw.9, because dropping it would make every page render per request (D-335, D-337; decided by the session under D-325; Daniel may supersede it).** Measured on 19/11 with two builds of main (Next 16.4.6): each page carries three inline scripts, the Turbopack bootstrap and the flight init (the same on every page) and one RSC payload script that differs per page and between two builds of the same tree; the course and lesson pages have no HTML at build time (rendered on first request, then cached) and the home, authors, credits and universities pages are regenerated at run time from the catalog in the database, so no build step sees the HTML the browser gets and no header can carry a hash per cached response. Next documents that nonces need dynamic rendering of every page, disable static generation and ISR and do not combine with PPR, and its experimental.sri covers only external chunks. A nonce on the dynamic routes alone would leave unsafe-inline on every static page. The cost of the whole fix is every page rendered per request (Lambda time and the CDN cache lost) for a risk the enforced policy already narrows (script sources limited to self and the playback hosts, frame-ancestors none, no inline event handlers in the code). The control is also partial because the site Lambda and its front door are defined outside this tree stacks; their HSTS, nosniff, referrer and frame headers are set by the site (security-headers test) and were seen live. So TAIL-site-csp-inline exempts CTRL-ssdf-pw.9 until 2027-02-19, owner administration, and it ends earlier when Next can emit the RSC payload outside an inline script or the site renders per request for another reason. Revert path: delete the exemption file, or let it lapse at its date.
