The checkout's pre-commit stage runs only if its hooks path points at the versioned hooks. install (push_guard.py install) sets core.hooksPath to push-guard.hooks_path when the checkout has none, and scripts/cloud/env.sh calls it, so a session that sources env.sh gets the stage (this amends D-237, which states the stage). A checkout whose hooks path is set to another value keeps it: install says so and does not override it, and the stage does not run there, by design. Evidence: the install test shows a commit refused by the stage after install and passed before it, and the env.sh test shows the path set after sourcing; both fail without the link.
