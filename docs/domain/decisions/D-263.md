The engine-gate-verdict battery is red on its time limit (12.6 s against battery.unit_time_limit 10 s). Three levels. Design: the battery runs a unit's script tests as one step in mode 'each', so the four files run one after another in one thread (gate-batch 5.7 s, gate-pin 7.0 s, gate-shadow 0.1 s, gate-verdict 0.6 s: 13.5 s), while the battery's steps run concurrently. Class: a step's files run in series wherever the mode is 'each', so the wall of a unit is the sum of its tests, not the slowest one. Case: this unit, which now holds three tests of about 6 to 7 s. Alternatives: (A) raise battery.unit_time_limit: a limit that hides the sum. (B) cut a test from the unit: every file here is the unit's (gate-batch, gate-pin, gate-verdict and gate-shadow are in its manifest) and each proves a case; cutting one loses it. (C) corrige a classe: one battery step per script test, so the wall is the slowest test (gate-pin, 7.0 s, under 10 s). Choice: C, in unit_battery.py (engine-units, lane 13), not in this unit: this unit cannot reach the limit by cutting without losing a case, and editing another unit's code is outside this lane. Not changed here.
