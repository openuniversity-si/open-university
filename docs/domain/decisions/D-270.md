A gate verdict FAIL opens its incident: `gate_report.main` calls `gate_incident.incident` and appends the gate-refusal record (head, mode, PR, failed stages, failing tests) to `incidents.jsonl` in the run's own logs, beside `stages.json`; a PASS writes nothing, and an incident that cannot be written prints one stderr line and never changes the verdict or the exit code. The register of incidents (docs/operations/incidents.md, D-240) therefore reads machine data and no one types a refusal by hand. Tested on a real `gate_report.main` run with fixture stage files (FAIL writes one record naming the head and the failed stage, PASS none, an unwritable incident leaves the verdict red and says so, and the record equals what gate_incident writes from the same report); the four tests fail without the call (1 failure, 3 errors).
