**PADRAO-DEV, how the chain reads history and the composed throughput validation (decided by the session under D-325, reported to Daniel through the Torre; it applies D-331 and may be superseded by him).** (1) A requirement whose implementing code came in before the Implements: trailer rule (D-317), or in a commit that carries no trailer, may name its implementing change in the requirement record: `implemented_by: [CHG-NNN | CHG-initial]`. The model reads it as an implements link from that change, which must exist and be merged, else a model error. The initial public tree (44ceca5, 14/11/2026, a root commit and not a merge) is read as one merged change, CHG-initial. A field is written only after the requirement's code is checked against that change's diff; a new requirement still gets its link from a trailer. (2) VAL-intention-ladder-1, which holds when every validation of the intention holds at once and so includes VAL-ladder-1, joins VAL-ladder-1 and VAL-escape-under-1 among the validations measured after the stop criterion of D-331: it cannot be met while the ladder is measuring, so it does not block a requirement while it is measuring, and it counts again once the ladder is met. Reason: history is never rewritten here, so without (1) ten requirements whose code exists could never close their chain; and without (2) D-331's exclusion of the ladder would be undone through a validation that contains it. Rejected: retiring slo.merged_prs_per_hour_min as superseded by VAL-ladder-1, because the hourly alert and the seven-day judgement serve different consumers. The proof is the chain computation and the implemented_by reader in scripts/lib/model.py, tested in scripts/tests/test_model.py. Revert path: a later decision that supersedes this one; the field and CHG-initial leave and the composed validation blocks again.
