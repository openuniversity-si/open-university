**PADRAO-DEV F7: security is the 17th system of the standard (Daniel's concern, 17/11/2026 15:03 BRT, through the Torre; the session's judgment, D-294).** Daniel asked why D-320 concluded that security does not become a system when elite organizations keep their own security management systems (an ISMS in the style of ISO/IEC 27001, product security programs, an SDL), and whether the criterion of one system per managed object leaves something out. The research (docs/programs/padrao-dev/phases/F7.md, a segurança reexaminada) found that the criterion holds (NIST SP 800-160 puts security into the 15288 processes, and the 27001 management system shares the harmonized structure of Annex SL with the whole model) but that D-320 applied it only to the objects the model already had. The reference practice manages four objects no system managed: the security risk with its treatment and accepted residual (27001 6.1.2, 6.1.3, 8.2, 8.3), the threat model of a component kept current as it changes (SDL), the vulnerability of our own code under a bug bar (SDL, SSDF Respond to Vulnerabilities) and the control with its applicability (the Statement of Applicability). So Segurança, the 17th system, manages RISK, THREAT, VULN and CTRL, and its own measure is the security posture; ADV and CRED stay in Fornecimento, whose object is the supplier relationship. The method gains a rule: a dimension's objects are listed from its reference practice before the model is searched for them; applied again to the dimensions left out, cost, accessibility and performance stay as decided and privacy adds REQUEST (a data subject's request under the LGPD) to Operation. This supersedes D-320 in its decision that security does not become a system, and decides PROP-security-system. The proof is the test of scripts/model, joined by the security system's own test when its types enter the model (F7d). Revert path: a later decision that supersedes this one.
